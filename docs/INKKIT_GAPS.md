# inkkit gaps

InkQuest depends on [inkkit](https://github.com/mohitagw15856/inkkit) for the
device layer and does not reimplement it. This file records the things InkQuest
needed that inkkit does not currently provide, so the workarounds are visible and
so inkkit has a candidate list of additions. Nothing here is worked around
silently.

## 1. No text or font engine

inkkit exposes the 1 bit framebuffer (`inkkit::Display`) but no way to draw text.
Its own `Display.h` comment notes that the apps render through their own
`FrameCanvas` (HabitInk) or `GfxRenderer` (InkCards), which live in the apps
rather than in inkkit.

**Impact.** "CrossPoint quality typography" is not achievable through inkkit
today. CrossPoint gets its quality from `GfxRenderer` plus compressed antialiased
`EpdFont` faces, none of which inkkit surfaces.

**Workaround in InkQuest.** `src/device/TextRenderer` brings its own compact 5x7
bitmap font (`src/device/Font5x7.h`, generated by `scripts/gen_font5x7.py`) and
does its own word wrapping (`inkquest::wrapText`, host tested). This is legible
but plain; it is not antialiased proportional type.

**Suggested inkkit addition.** A shared text/glyph module (a small `Text` or
`Canvas` helper over the framebuffer, and optionally a bridge to the ecosystem
`EpdFont` faces) so every inkkit app can render quality type without re deriving
it. InkQuest would drop its bitmap font and bind to that.

## 2. No image decoding

inkkit provides byte streams (`SdFileReader`) but no image decoder. Story covers
are BMP images that must be turned into pixels.

**Workaround in InkQuest.** `src/core/Bmp` is a small host tested BMP decoder
(1 bpp and 24 bpp, streamed a row at a time) and `src/device/BmpCover` plots the
result into the framebuffer.

**Suggested inkkit addition.** A streaming 1 bit image blitter (BMP at least)
over the framebuffer, since any app showing icons or covers needs the same thing.

## 3. Directory iteration is unconfirmed

`inkkit::sd::listFiles` is exactly what InkQuest needs to build the library
screen, but inkkit's own source marks the underlying SDK directory iteration API
as unconfirmed (`TODO(hardware-test)`). InkQuest relies on it as is and records
the on device check in `docs/HARDWARE_TESTING.md`.

**Suggested inkkit addition.** Once the SDK iteration API is confirmed on device,
remove that caveat from inkkit so dependants can rely on it without carrying their
own hardware test note.

## 4. No high level input helper

inkkit's `Buttons` gives raw edge queries by index, which is the right primitive.
InkQuest layers its own logical button map (`Config::Button`) on top. This is not
really a gap, just a note that the mapping from physical buttons to logical roles
lives in each app and is hardware specific.
